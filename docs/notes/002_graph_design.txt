Graph design and implementation
===============================
26 October 2026

The application is a standalone HTML page served directly from docs/index.html.
Its nodes and edges arrays own graph data. A change to the page is immediately
a change to the site; no separate build or duplicated versioned entrypoint exists.

Interaction
-----------
The overview shows every relationship and auto-arranges with Cytoscape's CoSE
layout. One pending arrangement owns computation, camera fitting, and reveal.
Keep the canvas hidden and announce “Arranging…” until Cytoscape reports that
it has rendered the fitted positions; frame-count delays do not prove readiness.
The graph's aria-busy attribute also controls canvas visibility, so accessible
and visible readiness cannot diverge.
Overview replaces the pending arrangement, cancelling both its scheduled work
and its render listener. Other controls do not cancel it. Fit and node movement
are disabled while arranging; search and concept details remain available.
Selecting a concept opens its details and highlights it while retaining the full
graph, positions, and camera. Overview closes the panel and rearranges the full
graph. Search, Fit, dragging, pan, and wheel zoom support exploration. Source context stays
behind a disclosure. Pointer buttons and keyboard arrows provide alternatives
to dragging.

Search keeps focus in the input while arrow keys choose a result; the first
Down selects the first result and the first Up selects the last. Escape closes
an open popup without clearing the query. Clearing the query, moving focus out
of the search control, or clicking outside dismisses the popup and clears its
active option. User activation by graph, search, or related concept returns
focus to the graph so its movement keys work. Restoring a selection from a URL
does not move focus.
Initial loads and later fragment changes share one parser. Malformed percent
encoding and unknown concept IDs open the overview, as does an empty fragment.
Valid encoded IDs select the concept without changing positions or the camera.
Selection and overview preserve the URL's existing query string.

Live layout is an explicit, page-local opt-in switch beside Fit, initially off.
A spring/repulsion loop lets visible nodes respond while the grabbed node stays
under the pointer. Turning it off freezes positions. The loop settles when idle
and pauses in a background tab. It preserves camera position during movement.
The live switch changes the motion preference without cancelling automatic
arrangement; motion starts after reveal and while the tab is visible.
Opening another concept's panel does not interrupt the simulation. Live layout
explicitly opts into motion, including with a reduced-motion system preference.
Panel resizing preserves the camera; Fit is available to reframe the graph.
Browser viewport resizing refits the graph through Cytoscape's existing resize
notification. There is no second container observer or resize notification.

Visual meaning
--------------
Subject controls color. Patterns have rounded solid cards; anti-patterns have
clipped corners, dashed borders, a warning fill and symbol. Dashed edges express
an editorial tension between concepts, independently of anti-pattern borders.

Each node declares conceptual generality: specific technique, domain practice,
or broad principle. Those levels set card size and text size. These are reviewed
scope judgments, not measured importance, popularity, or connection counts.
Selection changes border weight without changing semantic size.

Validation and limits
---------------------
Source checks cover graph references, complete generality classification,
relationship field types, connectivity, local links, and privacy patterns.
Browser checks exercise node details without filtering or repositioning, overview, dragging, search,
source disclosure,
node sizing, anti-pattern styling, live-layout switching and cancellation,
settling, camera stability, and desktop/mobile layout. Chromium-emulated touch
also exercises the switch and responsive neighbors. No browser runtime errors
were observed. Physical touch devices, other browser engines, and screen-reader
announcements remain unverified. No exhaustive accessibility audit is claimed.

The optional make check-browser command runs the graph lifecycle regressions
against a local Chromium executable without package dependencies. It checks
render-before-reveal, live switching before computation and before presentation,
replacement of pending arrangements, selection and disabled movement controls
during arrangement, stable camera and positions through details and selection,
keyboard movement and switching, dragging with live motion, viewport refitting,
and a fresh narrow deep link with reduced motion. Touch input checks dragging
with live motion off and on, switching, freezing, and camera preservation.
HEADED=1 additionally checks native tab visibility, pausing, and resuming in a
full Chromium build with a display; headless targets do not report background
visibility and cannot establish that behavior.
Both modes check that idle motion settles while the switch stays enabled and
that moving the selected node starts neighbor motion again without reframing.
Two failures were reproduced before correction: switching live layout during
arrangement left the graph hidden indefinitely; resizing from desktop to phone
width left every node outside the canvas. Both checks now pass. Browser checks
normally launch Chromium with an isolated temporary profile. CDP_PORT instead
attaches to a running local Chromium and closes only its temporary test tab.
Unless HEADED=1, that tab uses focus emulation and a small screencast capture
to keep frames running even when the window is minimized; captured images are
immediately acknowledged and discarded. This capture mode leaves the existing
window state and original tab untouched. It establishes interaction and rendering
behavior, not native background visibility. Other engines remain unverified.

The public repository starts with a reviewed clean history. Private research and
historical local snapshots are excluded from both its files and its ancestry.
Only docs/ is uploaded as the Pages artifact; developer tooling stays outside it.
